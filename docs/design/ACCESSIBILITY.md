# Accessibility

> **Purpose:** the WCAG 2.2 AA strategy, built into the component system rather than bolted on.
> **Audience:** UI implementers/reviewers. **Belongs here:** the a11y contract. **Lives elsewhere:** tokens (DESIGN_SYSTEM.md), per-screen behavior (UX_PATTERNS.md), the mode system (brand/BRAND.md §5).

Target: WCAG 2.2 AA. Enforced in the component layer + CI (axe-core scans on core pages inside `pnpm test:e2e` fail the build on serious/critical).

- **Contrast:** `pnpm check:contrast` verifies **78 token pairs** over `src/styles/tokens.css` — computed from the design system's own usage notes, not eyeballed. Per theme (35 pairs): `text` on bg/surface/raised 7 · `text-secondary` on surface/bg 4.5 · `text-tertiary` on surface 4.5 and on bg 3 (slate is 4.43 on the light canvas — **caption text sits on surface**) · `on-primary`/`primary` 4.5 · `gain-text`, `loss-text`, `warning-text`, `info-text` on surface and on their tint 4.5 · `gain`/`loss` on surface 3 (icons, arrows, numerals ≥ 24px only) · `lime-text`/surface 4.5 · `on-tint` on the five bloom tints 4.5 · each category hue (`cobalt`, `violet`, `tangerine-deep`, `blush-deep`, `mustard-deep`) on its tint 3 · `on-bloom` on cobalt and violet 3 · the four hero pairs (`on-hero` 7, `on-hero-secondary` 4.5, `hero-gain`/`hero-loss` 3); plus the four hero pairs re-run on both live-mode composites (black hero). **Never weaken pairs — extend them.** White on mustard/blush/tangerine is not paired because the app does not render it.
- **Mode independence:** paper/live is signalled three ways (texture grain, the black live hero, the `role="note"` text ribbon) — never colour alone. Removing any one is review-blocking (BRAND.md §5).
- **Keyboard:** full paths for search → instrument → ticket → confirm, and order cancel flows; the **lime focus ring — 2px `--focus`, 2px offset — on every interactive component** in both themes (`:focus-visible` globally, `.is-focused` in the bundle); no keyboard traps; native `<dialog>` provides focus trapping and Esc; segmented controls use `aria-pressed`.
- **Color independence:** every delta carries sign + arrow + colour with `sr-only` "up"/"down" text; order states are tags with **icon plus word**, never colour-only dots; bloom icon chips are decorative — the label text carries the category; the Donut/allocation legend repeats every value in text.
- **Live regions:** order-status changes and toasts announce via `aria-live="polite"` — genuinely exercised by the async execution lifecycle. The status banner is `role="status"`.
- **Forms:** real `<label>`s; errors linked via `aria-describedby`; zod messages surfaced as text, not colour alone; `inputmode="decimal"` on numeric inputs.
- **Tables:** `<th scope>`, captions; the ≤767px list-row collapse keeps proper list semantics.
- **Charts:** canvas charts are decoration-plus — a "View data" `<details>` table fallback carries the same information; the hero curve's hover readout is mirrored in that table.
- **Motion:** CSS transitions only (150–250ms, from an already visible state); no entrance animation on data, so a value never moves while being read. `prefers-reduced-motion: reduce` collapses every transition and keyframe to a single near-instant run (never an infinite animation at 0.01ms — that strobes).
- **Touch:** targets **≥ 44px** (`--touch-target`; `.ar-btn`, `.ar-input`, `.ar-chip`, `.ar-seg__item`, `.nav-link` under `pointer: coarse`); icon buttons are 40px with a 44px hit area; the tab bar is **84px including the safe-area inset** with the centre Trade disc; sheet grabbers are optional — buttons are always present.
- **Type:** Figtree at the system scale; body 16/24; captions never below 13px; money values wrap rather than truncate under large text; tabular numerals and consistent decimals keep figures scannable; the hero figure is 40px/700 so the headline number is legible at arm's length.
