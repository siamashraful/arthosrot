# Responsive behavior

> **Purpose:** how each major surface adapts structurally across breakpoints — never a shrunken desktop.
> **Audience:** UI implementers/reviewers. **Belongs here:** the adaptation matrix. **Lives elsewhere:** tokens (DESIGN_SYSTEM.md), screen content (UX_PATTERNS.md).

Breakpoints (as built in `globals.css`): `max-width: 767px` (mobile) · `max-width: 1023px` (tablet) · `pointer: coarse` · `prefers-reduced-motion` · `prefers-reduced-transparency`. Touch targets ≥ 44px. Respect safe-area insets (bottom nav, sheets). `inputmode="decimal"` on numeric inputs.

| Surface                   | ≥ 1024                                                                      | 768–1023                                       | ≤ 767                                                                                                                   |
| ------------------------- | --------------------------------------------------------------------------- | ---------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------- |
| Shell                     | Fixed left glass sidebar (`.shell-nav`, icon+label pills)                   | Sidebar collapsed to icon pills                | Glass `.mobile-top-bar` (lockup + search icon) + glass `.bottom-nav` (5 pills, 48px targets, safe-area padding)         |
| Mode ribbon               | Glass strip above the shell, `--ribbon-h`                                   | Same                                           | Same — never hidden                                                                                                     |
| Dashboard                 | Hero card + `.tile-row` (4 tiles) \| positions, watchlist, orders, activity | Single column; tiles 2×2                       | Single column, hero first, tiles 2×2, then `.list-row` sections                                                         |
| Tables (positions/orders) | True `.data-table`: tabular numerals, right-aligned, sortable               | Same, fewer columns                            | `.data-table.collapsible` — each row becomes a two-line `.list-row` (symbol + qty / value + P&L), not horizontal scroll |
| Ledger/activity           | `.list-row` list grouped by day                                             | Same                                           | Same                                                                                                                    |
| Instrument page           | Chart left ⅔, trade ticket docked right ⅓ (`.ticket-docked`)                | Chart full width, Trade button opens the sheet | Same; ticket opens as a bottom sheet (native `dialog.sheet`, glass, safe-area aware)                                    |
| Trading ticket            | Docked panel                                                                | Bottom sheet                                   | Bottom sheet — identical fields/summary/confirm at all sizes                                                            |
| Charts                    | Hero curve height clamp 200–320px; hover crosshair + glass readout          | Same                                           | Range selector becomes a scrollable segmented control; tap-crosshair                                                    |
| Dialogs/confirmations     | Centered `dialog.sheet`                                                     | Centered                                       | Bottom sheet (`sheet-up`, top corners `--radius-panel`)                                                                 |
| Omnisearch                | Cmd/Ctrl-K palette (post-MVP)                                               | Same                                           | Full-screen search from the top-bar icon                                                                                |

Rules: navigation is persistent (no hamburger-only navigation); trading actions remain fully usable on touch; the mode ribbon and freshness indicators appear at every breakpoint; glass chrome at ≤767 is limited to the top bar, bottom nav, ribbon, and sheets — content scrolls beneath it and must stay legible through it (text on glass is gated against the solid fallback); E2E runs both desktop and mobile viewport projects (playwright.config.ts).
