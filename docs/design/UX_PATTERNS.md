# UX patterns & screen specs

> **Purpose:** wireframe-level intent for each major surface + the standing state catalog every page must implement.
> **Audience:** UI implementers before building any screen. **Belongs here:** screen behavior + states. **Lives elsewhere:** visual system (DESIGN_SYSTEM.md), the as-built class mapping (DESIGN.md), breakpoints (RESPONSIVE_BEHAVIOR.md).

## Information architecture

Five sections — Dashboard `/` · Search `/markets` (labelled Search: finding a stock is the job; browse sits below), `/markets/s/[slug]`, `/i/[symbol]` · Portfolio `/portfolio` · Orders `/orders` · Activity `/activity`. Account/settings via the sidebar (desktop) and the top-bar icon buttons (phone). The nav marks the section a page belongs to (`aria-current="page"`): an instrument page `/i/[symbol]` lights **Search**, where it is found. Global: omnisearch (Cmd/Ctrl-K — **post-MVP**; phones reach search via the top-bar icon), the persistent **mode ribbon** ("Practice: simulated money" / "Live preview: real trading isn't available yet"), market status + data freshness in the shell, and the **status banner** — the system's warning Banner — when the event pipeline degrades ("Order updates may be delayed; last sync 10m ago", driven by `/api/v1/system/status`).

## Screens

- **Dashboard:** the **hero card** = portfolio value (`.ar-hero__value`, display 40/700) + day change (signed, arrow, `--hero-gain`/`--hero-loss`, sr sign text) + an as-of line naming the session in words ("as of 2:14 PM EDT · Market open") + three quick-action pills (Trade, Portfolio, Activity) — no chart in the hero; below it the Accounts tiles — **Stocks** as the cobalt bloom tile, **Cash** as the paper-and-tint tile with the cash chip; the net-worth chart with period pills in its own content card; insight cards for Buying power and Realized P&L (one tinted chip each, value in `--text`); then positions (top 5 + link), watchlist (holding-form rows: logo, symbol + name, the session sparkline (≥ 480px), price + day change; each row links to the instrument and carries a remove control; one freshness chip for the list in the section header; "N/A" when a symbol has no quote) and open orders as list rows. Each panel loads, empties and fails on its own: a failed account summary, watchlist or net-worth history shows an inline error with **Try again**, never an endless skeleton or a misleading empty state; watchlist remove is per row. Empty state (`.ar-empty`) teaches: "Search a symbol to place your first paper trade" with inline search. Under `data-mode="live"` the hero and tiles render live's own $0.00 empty states on the black hero.
- **Search (`/markets`; search, then browse):** the search field on top; with an empty query the screen is **Browse** — a full-width **Top 100** card (largest US companies by market value, "updated {date}", five stacked logos) then the 11 sectors as one list card (`ar-card--list`) of account-form rows: 40px Stocks chip with the sector's glyph, name, "N companies", three stacked logos and a chevron — a list, never a grid of same-size icon-heading-text cards. Typing replaces Browse with search results; clearing brings it back. A status line says "Searching…" until the results answer what is typed (the 300ms debounce plus the fetch), then the result count; "No matches for “X”" (with a hint) appears only once that search has answered; a failed search is an error with **Try again**, never "No matches". Input is capped at the server's 40-character limit. Each card or row is one link whose visible text is its accessible name. **Top movers** sits inside Browse, between the Top 100 card and the sectors: a Gainers | Losers segmented control over one list card of up to five rows (logo, symbol, name, price, day change with sr "today"/"last session"), ranked by exact percent across the Top 100 and the sectors, one freshness chip, "No gainers yet today." when nothing qualifies; never "most active".
- **Browse list** (`/markets/s/[slug]`): app bar with back chevron and the list name; an intro card (icon chip, one plain-language sentence, "N companies" or — for the Top 100 — "Ranked by market value · updated {date}", and one freshness chip for the list's prices); then rows: rank (Top 100 only — the order carries information), logo, symbol, name, last price, **day change** (sign + arrow + sr-text "today"/"last session"); "N/A" when a symbol has no quote. 25 rows, then "Show more"; a page that fails to load keeps the rows already shown and adds an inline alert ("Show more" retries). A list that fails outright offers **Try again**. Unknown list → app bar "List not found" and "This list doesn't exist." with a way back.
- **Instrument page:** app bar with back chevron; SYMBOL as a sky tag · `SymbolLogo` chip · name · **Bid / Ask / Last** with sizes · **day change vs the previous close** (sign, arrow, sr-text) · freshness chip ("IEX · 12s ago" / "Market closed · at close"); chart with period pills (1D–5Y; 1D is the most recent session, so it still draws on weekends and before the open) that scrubs to a price, its change since the range opened and the bar's date/time; **Stats** under the chart — the system's two-column hairline stats grid (`.ar-stats`) with Market cap, P/E (TTM | FY), 52-week high, 52-week low; "N/A" when a figure is unavailable, "n/m" for a loss-making P/E, and a one-line caption footnote naming the sources; "Your position" strip if held (account data visually separated from market data; never shown in live preview); a watchlist toggle (Add to / Remove from watchlist, `aria-pressed`); docked ticket or pinned Trade bar — shown once the account is known (skeleton while loading, an "Open your account to trade" card when there is no active account). The ticket pre-checks orders certain to be rejected — selling shares not held, a buy estimate above buying power, a market buy whose hold (price × qty × (1 + `MARKET_BUY_BUFFER`), sent as `trading.marketBuyBuffer` on the instrument response and computed exactly in `src/lib/order-ticket.ts`, parity-tested against core) is above buying power, with copy that explains the extra hold — before review; the server stays the authority. Unknown or malformed symbols get an "Unknown symbol" empty state; any other load failure is an error card with Try again (never mislabelled as unknown). A known symbol with no quote (delisting) is limit-only and sell-only: Market is disabled with "Market orders need a live quote. Use a limit order.", the ticket opens on Sell, and Buy explains the symbol is no longer tradable. A failed buying-power read shows an error card with retry; only a missing/unfunded account shows "Open your account to trade". Execution price on order detail is visibly distinct from displayed quote ("Filled at 200.13 · quoted 200.10 at submit") — never a fabricated explanation for the difference.
- **Trading ticket:** segmented **Buy/Sell** (labelled, neutral) → type (Market/Limit) → qty stepper/input → limit price (limit only) → live estimate rows (`.ar-ticket-row`: est. value using ask for buys / bid for sells, est. fees, buying power remaining or sellable shares) → Review → `.review-summary` ("Buy 10 AAPL · Market · est. $2,000.00 · Practice account — simulated money") → single primary pill Confirm. Disabled states always carry a reason: quantity (whole shares, 1 to 1,000,000) and limit price (> $0, ≤ 4 decimals) show inline field errors; mid-typing ("150.") stays quiet. Estimates are exact (integer cents, HALF_EVEN; `src/lib/order-ticket.ts`). One idempotency key per order intent: a refusal (insufficient buying power or holdings, delisted, no account) returns to editing with plain copy; a network failure or 5xx keeps the review open with "We couldn't confirm the order went through. Confirming again is safe: it won't be placed twice." and Confirm re-sends the SAME key (a replay, never a second order). Placing, cancelling and every observed fill or final state refresh all cash-derived views (`CASH_DERIVED_KEYS` + order caches; `src/components/finance/order-queries.ts`). On submit, the ticket closes into an order chip showing **Pending** (warning tag, icon + word) with a `FillProgress` bar that advances live — never optimistic FILLED — and a "View order details" link. Success is the quiet `.ar-success-mark` and the fill summary; no flourish.
- **Orders:** filter chips Open / History; rows: side, symbol, `FillProgress` + filled/total qty, type + limit, `OrderStatusBadge` as a tag with icon + word (Pending, Open, Partially filled, Filled, Cancelling, Cancelled, Rejected, Expired, Failed to submit), time; inline cancel (per-row pending state; a refused cancel shows the venue's reason beside the row). Load failures show an error card with Try again; with no active account the list points to the dashboard. Detail: "Order not found" for a missing/foreign order id, an error card with retry for any other failure; a **Cancel order** action (secondary button) while the venue still accepts one, canonical event timeline (source-labelled: broker / local / inferred / reconciliation) + fills + venue reject reason when present.
- **Portfolio:** hero card summary; insight cards for Cash, Positions value and Realized P&L (one tinted chip each); positions table (Symbol, Qty, Avg cost, Last, Market value, Unrealized P&L) on wide screens, list rows on phones (`data-table.collapsible` — symbol + qty / market value + unrealized P&L; avg cost and last are `data-cell="wide"`, wide screens only); with no active account, an empty state pointing to onboarding on the dashboard, never a load error. **Not yet built** (tracked in ROADMAP deferred gaps): day change, unrealized P&L % and weight columns; a realized P&L history section; the allocation bar (a single horizontal stacked bar in bloom hues by category with values in text — no pie).
- **Activity:** list rows grouped by market-time (ET) day under `.ar-group-label` headings ("Today", "Yesterday", else "Sep 30, 2026"), each row's sub-line the type and time; each entry: a semantic chip as in the system's Activity screen (money in → gain chip + `arrow-down-left`, amount in `--gain-text` with +; withdrawal or fee → loss chip + `arrow-up-right`, amount in `--text` with −; a trade → the Stocks chip with `stocks`; mapping in DESIGN.md → Iconography), description ("Bought 10 AAPL @ 200.00"), signed amount, link to the causing order (**not yet built**: TRADE/FEE entries reference the fill, and the ledger API exposes no order id); access to archived-account history after resets. History pages 50 entries at a time ("Show older activity") on a server keyset cursor over `(created_at, id)` — entries posted in one transaction share a timestamp, so a time-only cursor would skip them. A failed older page keeps the entries already shown and says so beside the button; a failed first load is an ErrorCard with Try again.
- **Auth:** minimal centred `.auth-card`; paper-trading disclosure at signup. Failures (weak password, existing email, wrong credentials, a network error) are a `role="alert"` line above the button, and the button never stays busy after one. Sign-in returns to `?next=` when it is a same-origin in-app path, else the dashboard; signed-in visitors to `/signin` or `/signup` go to the dashboard.
- **Settings:** setting rows; display name, theme, trading-mode switch (segmented; confirm sheet names the mode in words; neutral copy, no flourish), account reset (type-to-confirm; explains archival).
- **Settings → Cash** (practice mode only; live preview keeps its non-functional `FundingSheet` shells): a content card of setting rows — Cash balance; **Available to withdraw** (= cash − cash reserved for open buy orders − pending withdrawals) with a one-line caption saying held cash can't be withdrawn and how much is held when any is; a **Pending transfers** list only while there are any (ListRow: deposit = gain chip + `arrow-down-left`, withdrawal = loss chip + `arrow-up-right`, signed amount, Pending tag), polled every 15s until they settle; **Add cash** (primary) and **Withdraw** (secondary — disabled with a visible reason when nothing is withdrawable). While the account is still provisioning the buttons are replaced by a note. Both open `CashTransferSheet` (native `dialog.sheet`, the FundingSheet layout): amount in `.ar-input` with a `$` prefix (dollars, ≤ 2 decimals, commas stripped, `inputmode="decimal"`), quick `.ar-chip`s (Add: $500 · $1,000 · $5,000; Withdraw: 25% · 50% · Max of withdrawable, rounded down to the cent), live pre-checks mirroring the server (min $1.00, max $50,000.00 per transfer, deposits ≤ today's remaining allowance, withdrawals ≤ withdrawable) as an inline `role="alert"` field error with Review disabled → review rows (Amount, Cash now, Cash after; withdrawals add Available to withdraw after; "Simulated money — no real funds move.") → one primary **Confirm deposit / Confirm withdrawal**, carrying one Idempotency-Key per review so a double-click or retry replays rather than moving money twice. Outcome: settled → the quiet `.ar-success-mark` + "Added $X" / "Withdrew $X"; pending (Alpaca sandbox, minutes) → Pending tag + "the sandbox usually settles in a few minutes"; a venue refusal (a 201 with state FAILED) → "Transfer didn't go through", the reason and "No money moved" in the loss tone (loss chip + `alert`) — never shown as success. Every amount is exact cents (`src/lib/cash-transfer.ts`); the server stays the authority and its subcodes map to plain copy.
- **Price alerts** (ADR-016; in-app only, email later): **Set alert** (secondary compact button with the `bell` glyph) in the instrument page app bar beside the watchlist toggle opens `AlertSheet` (native `dialog.sheet`, the CashTransferSheet shell with `SheetHeader`): the **last price with its freshness chip** ("N/A" plus a note when there is no quote), "Alert me when the price goes" as an `.ar-seg` **Above | Below** (labelled, neutral: a direction is never green/red), the price in `.ar-input` with a `$` prefix (≤ 4 decimals, `inputmode="decimal"`) **prefilled with the current price** and selected, so typing replaces it. Pre-checks mirror the server (format, > 0) and refuse a level the price already meets ("AAPL is at $200.00 now. Pick a price above it."), shown only after the user edits; the help line explains the rule (market hours, fresh prices, alerts once). One primary pill **Set alert**; the result is a quiet status line ("Alert set: AAPL above $210.00." or, for a duplicate, "You already have this alert"). At 50 active alerts the button disables with the reason. Below: "Active alerts for AAPL" as ListRows (neutral `bell` chip, "Above $210.00", Active, an `x` delete icon button named "Delete alert: AAPL above $210.00"). The **bell** (`AlertsBell`) sits in the phone top bar between Search and Settings (40px icon button) and in the desktop sidebar as an "Alerts" row; unread triggered alerts show as a **small `--info` dot, never a number** (no count badges anywhere; the tab bar is never badged), and the count is in the accessible name ("Alerts, 2 unread"). It opens `AlertsPanel`: **Triggered** first (info `bell` chip, title link "AAPL crossed above $210.00" to the instrument page, sub "$210.35 · 10:42 AM ET" = observed price and the quote's market time, a neutral **New** tag on rows that were unread when opened, **Re-arm** and delete), then **Active** (neutral chip, "AAPL above $210.00", "Set Sep 30, 2026", delete), then a caption. Opening marks the shown alerts read (the dot clears). Empty: "No price alerts yet" + how to set one. Loading/error via `@/components/states`. The bell polls every 60s; that poll and the list both evaluate the user's alerts.

## Motion patterns

| Pattern          | Behavior                                                                                                                                            |
| ---------------- | --------------------------------------------------------------------------------------------------------------------------------------------------- |
| Sheet open/close | Native `<dialog>` — `sheet-up` (16px rise) over `--duration-base` 250ms `--ease-out-expo`; `::backdrop` is the scrim. Close is instant.             |
| Press feedback   | Buttons, tiles and nav rows scale to 0.98 while pressed (`--duration-fast`); rows and secondary buttons take the `--pressed` overlay. Nothing else. |
| Selection        | Chip, segment and toggle changes over `--duration-fast` 150ms.                                                                                      |
| Status change    | `OrderStatusBadge` plays `pulse-in` (`.ar-tag--beat`) on a state CHANGE only, never on mount — a state either is or is not; no crossfade.           |
| Fill bar         | Width transitions over `--duration-base`; the only motion attached to order data, and it moves toward a fact, never a verdict.                      |
| Skeleton         | Static `--divider` blocks mirroring the final layout (no shimmer).                                                                                  |
| Forbidden        | Entrance animation on data (stagger, rise-in) · anything that reacts to a fill, a gain, a loss, or the paper→live switch with celebration.          |
| Reduced motion   | Every transition and keyframe collapses to one near-instant run.                                                                                    |

## Status banner

The system's **warning Banner** (`.status-banner`, `role="status"`) directly under the mode ribbon; appears when `/api/v1/system/status` reports a degraded pipeline and stays until it clears. Copy names the condition and the last sync time. It never auto-dismisses and never animates; order rows show their last-synced context while it is visible. It describes the paper order pipeline, so it never shows in live preview. If the status endpoint itself fails it says "System status unavailable" rather than staying silent.

## Standing state catalog (every page)

| State              | Behavior                                                                                                                                         |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------ |
| Initial load       | Route-level skeletons (`.ar-skel*`) shaped like the content — no blank screens, no layout shift                                                  |
| Background refresh | Quiet stale-while-revalidate; no motion on the updated value                                                                                     |
| Partial failure    | Page renders what it has; failed panel shows an inline loss Banner with retry                                                                    |
| Provider outage    | Quotes show last cached value + a warning tag "Stale · as of 14:02 ET"                                                                           |
| Pipeline degraded  | Status banner; order rows show last-synced context — never fake "live"                                                                           |
| Market closed      | Prices labelled "At close"                                                                                                                       |
| Network loss       | Offline banner + mutation disabling (**post-MVP**); failed mutations surface inline errors today                                                 |
| Empty              | Teaching empty states (`.ar-empty`: heading, one sentence, one primary action)                                                                   |
| Auth required      | Redirect to signin preserving return path (`?next=`, same-origin paths only); a 401 under an open page does the same once                        |
| Unknown URL        | `not-found.tsx`: the auth chrome's centred card, "Page not found", one way back (Go to dashboard)                                                |
| Render failure     | `error.tsx` boundaries (in-shell and root): "Something went wrong", Try again, the error digest as a reference — never a claim about the account |
| Live preview       | Live's own empty states; paper data never renders under `data-mode="live"`                                                                       |

**Hard rule:** a rendered price without its timestamp/freshness state is a review-blocking bug.
